# Route handlers that are intentionally reachable WITHOUT authentication.
# The scanner (security/scan.py, check R1) treats any State<AppState> handler
# lacking an AuthSession param as a finding UNLESS its name is listed here.
# Keep entries to genuinely public endpoints; everything else must require auth.

# Account creation (no account exists yet to authenticate against)
post_register

# Auth challenge / verify: bootstrap device login before a session exists
get_challenge
post_verify

# Device enrollment bootstrap: first device proves identity via signed challenge
post_enroll
post_enrollment_package
get_enrollment_package

# Enrollment v3 claim (audit P-1). Unauthenticated by necessity: the joining
# device has no identity yet — creating one is what it is asking for. It is not
# open, though. The caller must know a live grant id, the grant can be claimed
# exactly once (atomic CAS, so a race is reported to the loser rather than
# overwriting), and the claim carries public keys only. Nothing here is readable
# without the session of the device that opened the grant. Re-review if the
# single-claim rule or that read restriction is ever relaxed.
post_claim

# Enrollment v3 result (audit P-1). Same necessity, one step further on: the
# joining device is asking which device_id the server minted for it, which is
# exactly what it is missing in order to authenticate. A session cannot be the
# gate here, so a signature is: every call must carry one over the grant id under
# the key that claimed the grant, verified before either branch answers, so an
# interceptor of the code cannot even learn whether a claim exists. Re-review if
# that signature check is ever made conditional.
post_result

# Recovery is pre-auth by design (user has lost their devices)
post_initiate
post_recover
post_enroll_device
post_register_start
post_register_finish
get_webauthn_config
post_register_start           # webauthn recovery registration (pre-auth)

# Share inbox delivery can be pulled by a not-yet-linked recipient token;
# scoped checks live inside the handler. (Review if this widens.)
get_inbox

# Web-session START is the browser (unauthenticated) creating a pending session.
# The poll (get_session) has no account to authenticate against either, but it
# is not open: it requires the poll secret registered at start (audit S-2 fix),
# checked by `check_poll_secret`. Re-review if that check is ever removed.
post_start
get_session
post_token
